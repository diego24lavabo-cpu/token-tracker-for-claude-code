## Decisions and deviations from the spec

**Repository**

- Mockups live in `docs/mockup/` but are gitignored: they show real project names. Files renamed `01-overview.png` to `09-settings.png`.
- TypeScript is pinned to `~6.0`: `typescript-eslint` does not support 7 yet.
- `release.yml` is deferred to step 11. CI uses Node 24 and `actions/checkout@v7`, `actions/setup-node@v7`.
- `scripts/gen-demo-data.mjs <projects-folder> [end-day]` writes a synthetic Claude Code `projects` folder: 5 fake projects, about 50 sessions over the 35 days ending today (or `end-day`), with subagents of every kind (task, workflow, `/btw`, warm-up, legacy inline lines with and without `agentId`). Seeded, so the same day gives the same data; fake paths only (`C:\Users\alex\dev\…`). It refuses the real log folders and any non-empty folder it did not write (it leaves a `.token-tracker-demo-data` marker). Used for the step 8 screenshots. **Step 11's demo mode should reuse it** (for example by generating into a temporary folder and scanning that into an in-memory database), rather than writing a second generator.
- No `electron-builder install-app-deps` postinstall. better-sqlite3 13 ships prebuilt Node-API binaries that load in both Node (tests) and Electron. `.npmrc` sets `ignore-scripts=true` and `electron-builder.yml` sets `npmRebuild: false`; Electron downloads its binary on first run.

**App shell**

- Sidebar items use the small square bullets of the mockup, not lucide icons.
- The packaged app cancels every network request and has a strict CSP; the dev server CSP allows HMR. Vite keeps every asset a file (`assetsInlineLimit: 0`) because the CSP blocks `data:` fonts.
- Dev runs use their own data folder, `%APPDATA%\Token Tracker for Claude Code (dev)`. Demo mode (`npm run dev:demo`) is only a flag so far; sample data comes in step 11.
- `vite.config.mts` deletes `ELECTRON_RUN_AS_NODE`, which VS Code leaks into child processes.
- Ctrl+1…8 (Cmd on macOS) open the sections, by physical key so AZERTY works.

**Reading the logs**

- Project = the directory a session folder stands for, recovered by walking `cwd` up until its encoding matches the folder name. `basename(cwd)` is only the fallback for a `cwd` outside that tree. Reason: `cd` into subfolders would otherwise split projects. The first-level subfolder is stored per response (`messages.subfolder`).
- Container folders: a folder project listed in the `container_projects` setting is reported under its first-level subfolders, named **`<folder> › <subfolder>`** (for example `VS Code › Astrophotography_TM`; `PROJECT_SEPARATOR` and `containerOf` / `subfolderOf` in `shared/projects.ts`). Responses at the top of the folder keep the folder's name. This is applied when the derived tables are built, so `messages` keeps the raw names and the flags can change without losing history. Because the full name is the project name in every derived table, every page, filter and export shows it as is (Overview main project, Sessions table and project filter, Agents top 10, CSV); only the Projects table shortens it under its folder.
- Duplicated responses: the key is `message.id:requestId`, global. The largest token values and the first stop reason win. When copies sit in different places, the owning main session beats copied history, which beats a subagent, which beats a `/btw` transcript. Files are read main sessions first, then oldest first.
- "Lines skipped" counts only unreadable lines (broken JSON, malformed assistant records), not the many lines without usage.
- Warm-up agent: a task or workflow agent with at most 1 output token in total and no stop reason. Warm-ups are not counted as invocations; `/btw` side questions are.
- Legacy inline sidechain lines without `agentId` form one `inline` agent per session.
- A last line without a newline is read, but the offset stays before it, so it is read again once complete.
- When the system time zone changes, local days and hours are recomputed from the UTC timestamps.

**Numbers**

- Durations are active time: the sum of gaps between consecutive responses, leaving out any gap over 30 minutes. A session's gaps run across all its responses, subagents included. The first-to-last span is stored too and is shown only in the session drawer (step 7).
- 1-hour cache writes are stored separately (`cache_write_1h`, part of `cache_write`) and priced at 2× input instead of 1.25×. `pricing.json` has five prices per model. Defaults come from Anthropic's price list cached on 2026-11-03, with a TODO to verify. Haiku 5.5's cache-read price is derived, and its price for prompts over 100K tokens is not modelled.
- Period comparison: "New activity" when the period before had under 5% of the current usage, otherwise a signed percentage.
- The Machines shortcut card ignores the machine filter.
- The streak counts back from today; when today has no usage yet, from yesterday.

**Calendar page**

- `getCalendar(machineIds?)` returns `{ hasData, today, heatmap, kpis, byWeekday, bestWeekday, byHour, byMonth }`. Only the machine filter applies. The main process decides today (`db.localDay(now)`) and sends it back; the page refetches when `useToday` changes, so the calendar rolls over at midnight.
- The 12 months = 365 days ending today (`today - 364` to today). They always span exactly 53 Monday-first weeks, because `today - 364` is the same weekday as today. `heatmap.weeks[i].days` has 7 entries, `null` for the days before the range (start of the first column) and after today (end of the last). Heatmap total = Overview total over `heatmap.from`…`heatmap.to` (tested).
- Heat levels are computed in the main process: 0 = no usage, 1 to 4 by quartile of the active days (`thresholds` = where levels 2, 3, 4 start). Quartiles rather than a share of the maximum, so one huge day does not turn every other day into level 1. The legend swatches give the token range of each level in their tooltip.
- KPIs: active days x / 365. The current streak is the same rule as the Overview (from yesterday while today is empty), now returned as `{ days, from, to }`; `currentStreak` in `aggregate.ts` returns that object and the Overview keeps `.days`. It also ignores `hourly` rows with 0 tokens now. The longest streak is counted inside the 365 days only (a run that started before is cut). Ties go to the most recent run and the most recent best day.
- By weekday and by hour cover the 365 days. By month covers the 12 calendar months ending with the current one (Dec 2025 to Nov 2026 on 2026-11-12): the first month starts on its 1st, a little after the heatmap's `from`, and the current month is partial ("so far" in its tooltip). The busiest weekday (`bestWeekday`, chosen in the main process) is drawn in `--accent-light` and named in the card header.
- Sessions per heatmap day = sessions **with activity that day**, subagents included, from the derived table `session_days` (one row per machine, session and local day with a response; step 10). A session that runs past midnight counts on both days. Start-day counting showed "55.5M tokens, 0 sessions" on real data. Other machines' sessions per day come from their sync files, so they are exact too.
- Clicking a day with usage navigates to `/sessions?day=YYYY-MM-DD` (`sessionsOfDay()` and `SESSIONS_DAY_PARAM` in `src/routes.ts`). Days without usage do nothing (`aria-disabled`).
- Heatmap UI (`src/components/Heatmap.tsx`): a CSS grid of `<button>`s with roving focus. The grid is one tab stop; the arrow keys move by a day (up/down) or a week (left/right), Home/End go to the first day / today. The tooltip opens on hover, and on keyboard focus only (`:focus-visible`), so a mouse click does not leave it stuck open. It sits above the cell, or below it when the card has no room above, and is kept inside the card horizontally. Today has a thin white inner border. Month labels sit over the column holding the 1st of the month, plus the first column when the next label is at least 3 columns away. Cells grow with the width, up to about 30 px (they fill a maximized 1920 px window).
- The header's period selector is disabled on this page (greyed, tooltip "The calendar always shows the last 12 months"): `Page periodIgnored`, `SegmentedControl disabledReason`.
- Layout: the three charts sit side by side from 1280 px (weekday, hour, month); below that, weekday and hour share a row and the months take the next one.
- New reusable pieces: `CategoryBars` (one labeled bar per category, optional highlight), `formatDay(day, { weekday: true })` → `Tue, Nov 10`, `formatMonth`, `en.dates.weekdays` / `weekdaysLong`. `HourBars` takes a `shareLabel`.

**Sync through Google Drive (step 10)**

- **Every page reads the same tables for every machine.** Three derived tables were added (schema 6): `session_days` (machine, session, local day with a response), `session_models` and `subagent_models` (tokens per model, 1-hour cache share included). They replace the four places where the aggregations read `messages` for this machine and fell back to "main model prices everything" for others (calendar sessions per day, Sessions day filter, session costs, agent type costs). Other machines' rows live in every derived table under their own `machine_id` (the design of step 2), not in separate tables. Test: a machine's Overview, Projects, project panels, Models, Calendar, Agents, Sessions (4 sort orders, 2 day filters) and every session drawer, computed on that machine, deep-equal the same pages computed on the other machine from its sync files (`tests/sync.test.ts`).
- **Files** (`electron/syncFormat.ts`, schema version 1): `<My Drive>/ClaudeTokenTracker/README.txt` (written once) and `machines/<machineId>/machine.json` (`schemaVersion, machineId, name, platform, appVersion, lastSync, years`) + `<year>.json`. A year file has `hourly` rows of 12 columns: SPEC §5b's 11 plus `cacheWrite1h` after `cacheRead`; `sessions` (id, project, model, start/end ISO, startDay, messages, activeMs, subagentCount, subagentTokens, `models` = `[model, input, output, cacheWrite, cacheRead, cacheWrite1h]` rows, `projects` = `[name, tokens]`, `days`); `subagents` (id, session, project, type, kind, model, start/end, startDay, calls, startupInput, activeMs, `models`). No session totals: they are the sum of `models`. Rows go in the year of their day / start day. One row per line, so a file stays readable; a year over 5 MB is written as `.json.gz` (read too; when both exist the newer wins). The fake Mac (51 sessions over 35 days) writes 105 KB. Descriptions, `tool_use_id`, paths and text are never read by the export (it reads only the derived tables), tested on the fixture.
- **Writing** (`electron/sync.ts`, `SyncService`): through `<file>.tmp` + rename (retried on EPERM/EBUSY). Only years whose text changed (SHA-1 kept in the `sync_written` setting, per folder) or whose file disappeared are rewritten. Schedule: after a scan that imported or completed records, a rebuild, a container/alias/name change: 60 s later, at least 5 min after the previous write; later changes do not push it back. At startup (after the first scan) and on "Sync now": at once. On quit: synchronously when a write is pending. `machine.json` (with `lastSync`) is rewritten with any year, on a name change, and as a heartbeat at least every hour, so an idle machine does not look stale. The app never creates the Drive folder itself: when the parent of `ClaudeTokenTracker` is missing (Drive not running), sync is `pending`.
- **Reading**: other machines' folders are listed every 30 s with `fs.promises.readdir` / `stat` (deviation: SPEC says chokidar in polling mode; a plain poll does the same, is simpler and easier to test). A changed file (size or mtime) is read, checked (`parseYearFile` / `parseMachineFile`: schema version, machine id = folder name, year = file name, every row; a malformed row is skipped and logged) and kept in `remote_files` (last good copy); then that machine's rows are rebuilt from all its stored years (`materialize`). A broken or partial file keeps the last good copy, is retried when it changes, and is logged once (`problem: 'unreadable'`). A newer schema: `newerVersion`. Conflict copies (`2026 (1).json`, `2026.json (1)`, `machine (1).json`) are ignored, logged once and counted. A machine appears only once its `machine.json` was read (it gives the name and platform). A machine whose folder disappears keeps its numbers (`problem: 'missing'`). The machine's own folder is never read.
- **Machines** table: `hidden` and `app_version` columns. "Remove" (Settings, native dialog) hides a machine: its rows leave the derived tables and it is skipped when reading; "Remove and delete its files from Drive" also deletes its folder. "Show again" rebuilds it from `remote_files`, without Drive. The local machine can be neither. Stale = no write for more than 7 days (`staleDays` in `shared/sync.ts`).
- **Folder detection** (`electron/drive.ts`): macOS `~/Library/CloudStorage/GoogleDrive-<account>/<My Drive>`, `/Volumes/GoogleDrive*/`, `~/Google Drive`; Windows: drive letters D–Z whose root has Drive's hidden `.shortcut-targets-by-id` folder (seen on this PC; a data disk with a "My Drive" folder is ignored), `%USERPROFILE%\Google Drive`, a mirrored `%USERPROFILE%\<My Drive>`. "My Drive" is matched in ~35 languages, or guessed when the root holds a single ordinary folder besides known "Shared drives"/"Other computers" names. Each folder listing has a 3 s timeout (offline network drives). With several accounts (this PC has two: `G:\Mon Drive`, `H:\Mon Drive`) the user picks; Windows shows each account from the volume label (`[System.IO.DriveInfo]` through PowerShell, only with ≥ 2 candidates; Windows cuts labels to 32 characters, `alex@example.com - Goo...`, handled). Exactly one found: used automatically when sync is turned on. None: the folder picker. Picking `ClaudeTokenTracker` itself or its parent both work. `useSyncFolder(path)` only accepts a detected candidate. Detection runs only while sync is on (cached 60 s).
- **Settings → Sync**: switch (off by default), the explanation of what is written and never written, status, folder + "Change…", the account list, this computer's name (editable, 60 characters, default the hostname), the machine list (platform icon, last sync, stale/problem/conflict warnings, Remove / Show again), "Sync now". Turning sync off stops reading and writing; other machines' last numbers stay (the title bar then says "Sync off · N machines").
- **Title bar**: "Google Drive · N machines · synced X ago" (orange dot), "Sync pending · Google Drive not reachable", "Sync on · choose a Google Drive folder in Settings" (hollow dot), "Local only" (grey dot). Status changes come through a new `syncUpdated` event, which does not refresh the usage pages; imported data sends `usageUpdated`. `useUsageQuery(fetcher, { syncStatus: true })` listens to both (Settings, Machines).
- **Container flags** apply to each machine's own data (synced names carry the source machine's split). A folder flagged on one machine only shows its unsplit usage from the other as the `<folder> (root)` child of the same group on Projects. Not extended further; aliases cover renames.
- **Time zones**: days and hours stay in the source machine's local time (SPEC §5b). Clock times (Sessions start, drawer) are shown in this machine's zone, so with machines in different zones a session's day and clock time can disagree by a few hours.

**Project aliases (step 10)**

- Stored as a list of `{ from, to }` in the `project_aliases` setting (a list, so a project named `__proto__` is harmless). Chains are followed (`A → B`, `B → C`); a cycle, a duplicate old name, an empty or identical name are refused (`aliasProblem` in `shared/projects.ts`, used by the UI and by `parseProjectAliases`).
- Applied when the derived tables are built, like container flags: locally through the SQLite function `tt_project(project, subfolder)` (cached per name), for other machines when their rows are rebuilt from `remote_files`. Rule (`applyAliases`): an alias of the full name, else an alias of the folder part (`VS Code › website` → `Code › website` with `VS Code → Code`). Container flags match through aliases (`containerTargets`): a flag set on the old name splits the new one too, and the Container folders card lists the renamed folder once, under its new name. Checked on the real logs with the user's own rename (flagged `VS Code` aliased to its new folder name): every subfolder followed, the flag was kept, no `VS Code` name was left. Real project names stay out of the repo: tests use `Code-2026`.
- The sync files carry the names as this machine reports them (aliases applied), so the other machines see the merged name even without the alias; each machine's own aliases also apply to what it reads. Changing aliases rebuilds both and schedules a write. The Projects page groups by name, so grouped subfolders follow.
- Settings card: the list (old → new, remove button) and two fields with suggestions (every project name shown, plus the stored folder names).
